The Symplax CLI is the `symplax` package on npm. It needs Node.js 18 or later.

```bash
npm install -g symplax     # or put npx in front of any command
symplax login
```

## Sign in

`symplax login` shows a short code and opens symplax.com in your browser.

<Steps>
  <Step title="Check the code">
    The browser shows the same code as your terminal, and the name of the machine asking.
  </Step>
  <Step title="Choose the access">
    Pick the workspace, personal or a team, what the CLI may do, and how long it stays signed in:
    30, 90 or 365 days, or no expiry.
  </Step>
  <Step title="Authorize">
    Click **Authorize**. The terminal picks up its key by itself and says who you are signed in as.
  </Step>
</Steps>

Over SSH, on a machine with no display, or with `--no-browser`, the CLI prints the link instead.
Open it on any device, your phone included, and enter the code.

The login is an [API key](/api/keys) named after your machine, such as "CLI on my-laptop". You
can see and revoke it in **Settings**, **API Keys**. `symplax logout` forgets it on this machine.

## Commands

| Command | What it does |
| --- | --- |
| `symplax apps` | Your apps, their status, server and URL |
| `symplax deploy [app]` | Deploy the latest code and follow the build until it is live |
| `symplax logs [app] -n 200` | The app's recent logs |
| `symplax restart [app]` | Restart the app |
| `symplax rollback [app]` | Go back to the last good deploy |
| `symplax servers` | Your servers |
| `symplax db list` | Your databases |
| `symplax db create <name> --engine postgres@17` | Create a database (add `--server <name>` if you have more than one) |
| `symplax apps create <name> --repo owner/repo` | Create an app from GitHub, deploy it and follow the build |
| `symplax env [app]` | The app's environment variables |
| `symplax env set <app> KEY=value` | Set one or more variables |
| `symplax env unset <app> KEY` | Remove one or more variables |
| `symplax env import <app> [file]` | Set every variable in a `.env` file |
| `symplax cron [app]` | The app's cron jobs and how they last ran |
| `symplax cron add <app> --schedule "..." --command "..."` | Schedule a command inside the app |
| `symplax cron edit <app> <job>` | Change a job's `--schedule`, `--command` or `--name` |
| `symplax cron pause <app> <job>` | Pause a job, and `resume` to start it again |
| `symplax cron logs <app> <job>` | A job's recent runs and their output |
| `symplax domain [app]` | The DNS record to create, and whether HTTPS works |
| `symplax domain set <app> <domain>` | Use your own domain, with HTTPS set up for you |
| `symplax whoami` | The account and key in use |
| `symplax logout` | Forget the saved login |

Leave out the app and you get a list to pick from with the arrow keys. You can also name an app
in any case, by the start of a unique name, or by its id.

## Set up a new app

```bash
symplax db create main --engine postgres@17
symplax apps create my-api --repo acme/my-api --db main --env-file .env.production \
  --release "npx prisma migrate deploy"
```

`apps create` makes the app, starts its first deploy and follows it. `--db` links the database
before that first build, so `DATABASE_URL` is already set when the release command runs. It also
takes `--branch`, `--server`, `--port`, `--root` for a monorepo, and `-e KEY=value`, repeated for
each variable.

Changes made with `symplax env` apply on the next deploy: run `symplax deploy <app>` after them.

<Note>
  Cron jobs need the Pro plan or higher. Deleting a cron job is done in the dashboard, because no
  API key can delete anything; `symplax cron pause` stops one from the terminal.
</Note>

## Following a deploy

```text
$ symplax deploy my-api

⬢ symplax  deploying my-api

│ Installing dependencies
✓ Building 1m 12s
✓ Starting on your server 19s

╭───────────────────────────────╮
│  ✓ my-api is live             │
│  https://my-api.symplax.app   │
│  deployed in 1m 48s           │
╰───────────────────────────────╯
```

If the build fails, the CLI says at which step, what went wrong and how to fix it, and exits
with code `1`. Press `Ctrl+C` to stop following; the deploy carries on.

## For scripts and AI assistants

- `--json` on any command prints JSON on stdout. Progress and messages go to stderr.
- Exit codes: `0` success, `1` failure, `2` a usage mistake, such as a name that matches two apps.
- Colors switch off when the output is not a terminal, or when `NO_COLOR` is set.
- The saved login is in `~/.config/symplax/config.json`, readable only by you.

<Tip>
  AI coding assistants that run terminal commands, like Claude Code, Cursor or Codex, can use the
  CLI directly: "deploy my-api with symplax, and if it fails, read the logs and fix it."
</Tip>

<Note>
  Each command needs its scope on the login: `apps:write` to create apps or change variables,
  cron jobs and domains, and `databases:write` as well to create or link a database. If one is
  missing, the CLI says which. Backups are managed in the dashboard.
</Note>
